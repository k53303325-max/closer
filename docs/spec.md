# Closer — ТЗ на MVP

Telegram-бот, в котором две стороны за несколько минут оформляют договор оказания услуг из готового шаблона, подписывают его кодом из СМС и получают PDF с листом подписания. Деньги бот не принимает.

Версия ТЗ: 29.10.2026. Источник истины для Cursor: этот файл, `templates/uslugi/fields.json`, `docs/pep_offer.md`.

---

## 1. Рамки MVP

**Входит**
- Telegram-бот на aiogram (без мини-аппа и веб-кабинета).
- Один вид договора — оказание услуг: договор + акт (`templates/uslugi/`). Подряд и поставка добавятся позже тем же механизмом: новая папка шаблона + `fields.json`.
- Стороны любого статуса: физлицо, самозанятый, ИП, ООО. Шаблон один — от статуса меняются только строка стороны, реквизиты и НДС (`closer/documents/parties.py`).
- Пользователь заполняет минимум: что за услуги, срок, сумма, порядок оплаты (кнопки). Всё остальное бот берёт из профиля или ставит сам.
- Подписание ПЭП: соглашение о ПЭП (оферта, `docs/pep_offer.md`) принимается галочкой в чате, ключ — одноразовый код в СМС.
- Журнал подписания с цепочкой хешей.
- Акт по тому же флоу подписания; приёмка по умолчанию через 5 дней молчания.
- Напоминания о подписании, сроке, акте и оплате.
- Первые 3 договора каждого инициатора бесплатно, дальше — разовая оплата договора (Telegram Stars или ЮKassa). Цену определим по себестоимости, ориентир 99 ₽.

**Не входит**
- Приём и хранение денег, безопасная сделка.
- Сделки с нотариусом или госрегистрацией.
- Свободное редактирование текста договора. Правится только значение полей.
- Претензии, разбор чужих договоров, проверка контрагента, «Мой налог».

**Готово, когда**
- Договор от первого сообщения до PDF у обеих сторон — не дольше 10 минут.
- Хеш PDF, указанный в журнале, совпадает с хешем файла у сторон.
- Журнал нельзя изменить задним числом (только INSERT, цепочка хешей сходится).
- 10 реальных договоров подписаны знакомыми исполнителями без помощи автора.

## 2. Роли и сценарий

| Роль | Кто | Что делает |
|---|---|---|
| Инициатор | Обычно исполнитель | Описывает сделку, проверяет поля, подписывает первым, отправляет ссылку, создаёт акт |
| Контрагент | Обычно заказчик | Открывает ссылку, принимает соглашение о ПЭП, заполняет профиль, подписывает или просит правку |
| Админ | Автор проекта | Шаблоны и их версии, журнал, выписки по запросу сторон |

Роль «Заказчик / Исполнитель» в договоре выбирает инициатор: первым вопросом «Вы оказываете услуги или заказываете?».

**Основной сценарий**
1. Инициатор: «Сделаю логотип за 45 тысяч до конца ноября, половина вперёд».
2. Бот (ИИ) извлекает `services`, `term`, `price`, `payment`; недостающее спрашивает по одному вопросу (формулировки — в `fields.json` → `ask`). `payment` — всегда кнопками.
3. Если профиль инициатора неполный — бот дозапрашивает только поля, нужные для его статуса.
4. Бот показывает карточку договора и PDF-черновик (водяной знак «ЧЕРНОВИК»). Кнопки: «Изменить поле», «Подписать и отправить».
5. Инициатор подписывает кодом из СМС → получает ссылку `t.me/<bot>?start=c_<token>` и готовый текст для пересылки.
6. Контрагент открывает ссылку → видит, кто приглашает, вид договора и сумму → принимает соглашение о ПЭП (галочка) → делится контактом → заполняет профиль (только поля своего статуса) → видит итоговый черновик со своими данными.
7. Контрагент подписывает кодом или нажимает «Предложить правку» (выбор поля + новое значение). Правка → новая версия, подпись инициатора сбрасывается, инициатор подписывает заново.
8. После двух подписей обе стороны получают: PDF договора (ровно тот файл, который подписан) + PDF «Лист подписания».
9. Дальше: напоминание о сроке → «Создать акт» → акт подписывается тем же флоу; отметки «Оплатил» / «Оплату получил».

**Важно про PDF и хеш.** Подписывается конкретный PDF конкретной версии. После подписей этот файл не пересобирается и не дополняется — иначе изменится хеш. Лист подписания — отдельный PDF, в нём хеш договора. Для удобства можно отдать и склеенную копию, но эталон — исходный PDF.

## 3. Профиль стороны

Профиль заполняется один раз и переиспользуется. Спрашиваем только то, что нужно для статуса.

| Поле | Физлицо | Самозанятый | ИП | ООО |
|---|---|---|---|---|
| ФИО (у ООО — подписанта) | ✓ | ✓ | ✓ | ✓ |
| Паспорт: только серия и номер | ✓ | ✓ | — | — |
| ИНН | — | ✓ | ✓ | ✓ |
| ОГРНИП / ОГРН | — | — | ✓ | ✓ |
| Наименование организации | — | — | — | ✓ |
| Должность подписанта (род. падеж) и основание полномочий | — | — | — | ✓ (кнопки: Устава / доверенности) |
| Адрес из ЕГРИП / ЕГРЮЛ | — | — | ✓ | ✓ |
| Телефон | из «Поделиться контактом» | ✓ | ✓ | ✓ |
| Реквизиты для оплаты: СБП или банк | только если сторона — исполнитель | ✓ | ✓ | ✓ |
| Режим НДС: без НДС / 22 % / 7 % / 5 % | — | — | ✓ | ✓ |
| Email | необязательно | | | |

Валидация: ИНН 10/12 цифр с контрольной суммой, ОГРН 13, ОГРНИП 15, паспорт 4+6 цифр. Подсказка в боте для статуса: «Не знаете свой статус? Если не регистрировались — физлицо».

## 4. Шаблоны и заполнение

- Шаблоны — Word-файлы автора в `templates/<вид>/`. Каждое поле — элемент управления содержимым Word с меткой (tag) = ключ поля.
- Заполнение — `closer/documents/docx_fill.py`: подставляет значения по меткам, снимает обёртки полей и серую подсветку, падает, если хоть одно поле не заполнено. PDF — LibreOffice headless.
- Описание полей, вопросы, форматы, варианты оплаты — `templates/<вид>/fields.json`. Тест `tests/test_docx_fill.py` сверяет метки шаблона со схемой.
- **Текст договора не генерируется и не меняется кодом.** ИИ только извлекает значения полей. Новые формулировки — только через новую версию шаблона от автора.
- Версия шаблона хранится в `contract_versions`: подписанный договор всегда воспроизводим.

**ИИ (GigaChat Lite через API Сбера, российская модель — обязательно)**
1. Классификация: подходит ли сделка под «оказание услуг»; если это продажа вещи, ремонт с материалами подрядчика и т. п. — вернуть `unsupported`, бот объяснит, что пока умеет только услуги.
2. Извлечение: JSON строго по схеме `services, term, price, payment` (значения `payment` — только ключи `prepay | postpay | split` или `null`).
3. Нормализация — в коде, не в ИИ: сумма в число, «3 недели» в дату, `services` в дательный падеж (продолжение фразы «оказывает услуги по …» — ИИ просим вернуть именно так, код проверяет, что не пусто).
4. Паспорт, телефон и реквизиты в ИИ не передаются никогда.
5. Клиент через интерфейс `LLMClient` — модель меняется конфигом. Цена GigaChat Lite ~0,065 ₽ / 1000 токенов.

## 5. Подписание ПЭП и журнал

Подпись — одноразовый код из СМС, привязанный к SHA-256 конкретного PDF конкретной версии.

1. Перед подписанием бот показывает PDF и первые 8 символов его хеша.
2. Код: 6 цифр, хранится только хеш с солью, живёт 5 минут, 5 попыток, повторная отправка не чаще раза в 60 с, не больше 5 СМС в час на номер.
3. Канал — только СМС на номер из «Поделиться контактом». Шлюз — самый дешёвый из SMSC.ru / SMS Aero, через интерфейс `SmsGateway`.
4. Верный код → событие `signed` в журнале. После второй подписи — `finalized`, генерируется лист подписания.

**Журнал** (`audit_log`, только INSERT; триггер запрещает UPDATE/DELETE)

| Поле | Зачем |
|---|---|
| время UTC | момент действия |
| событие: `offer_accepted`, `contact_shared`, `viewed`, `code_sent`, `signed`, `edit_requested`, `declined`, `finalized`, `act_silent_accept`, `paid_marked`, `payment_received` | ход сделки |
| Telegram ID, username, телефон | кто |
| версия документа и SHA-256 PDF | что подписано |
| версия соглашения о ПЭП | на каких правилах |
| id отправки СМС у шлюза | доказательство отправки кода |
| `prev_hash`, `record_hash` | цепочка: подмену любой записи видно |

IP и устройство в Telegram недоступны — не пишем.

**Лист подписания (PDF)**: номер и вид документа, SHA-256 документа, стороны (ФИО, телефон с маской `+7 9•• •••-••-12`), время каждой подписи, версия соглашения о ПЭП, как проверить (`/verify`).

**`/verify`**: пользователь присылает PDF → бот считает хеш → отвечает, есть ли он в журнале, кто и когда подписал.

## 6. Акт, напоминания, оплата

**Акт** создаёт исполнитель кнопкой в карточке договора или по напоминанию. Поля копируются из договора (`fields.json` → `act_copies_from_contract`); исполнитель подтверждает даты `start` (по умолчанию дата договора) и `end` (по умолчанию сегодня). Подписание — тот же флоу. Заказчику — кнопки «Подписать» и «Есть недостатки» (текст обязателен → исполнителю; после исправления — новый акт).
**Молчание 5 дней** после доставки акта заказчику → событие `act_silent_accept`, договор «Исполнен», обеим сторонам сообщение (п. 10 договора). Акт в этом случае подписан только исполнителем — это нормально, в листе подписания так и указано.

**Напоминания** (воркер каждые 10 минут)

| Когда | Кому |
|---|---|
| ссылку не открыли 24 ч | инициатору: «Переслать снова» |
| открыли, но не подписали 48 ч | контрагенту, потом инициатору |
| за 3 дня до срока и в день срока | обоим; исполнителю — «Создать акт» |
| акт без ответа 3 дня | заказчику: «Через 2 дня акт будет считаться подписанным» |
| срок оплаты по `payment` | заказчику: реквизиты + «Оплатил» |
| «Оплатил» без «Получил» 48 ч | исполнителю |

Самозанятому после «Оплату получил» — напоминание сформировать чек в «Мой налог».

## 7. Статусы договора

`draft` → `awaiting_counterparty` → (`changes_requested` → `draft`) → `signed` → `completed` (акт подписан или принят молчанием).
Боковые: `declined`, `expired` (ссылку не открыли 7 дней), `cancelled` (инициатор удалил до второй подписи).

## 8. База данных (PostgreSQL)

| Таблица | Ключевые поля |
|---|---|
| `users` | id, tg_user_id (unique), tg_username, phone, phone_verified_at, free_contracts_used, deleted_at |
| `profiles` | user_id, status, full_name, passport_enc, inn, ogrn, org_name, signer_position, signer_basis, address_enc, email, bank, sbp, vat_mode |
| `consents` | user_id, kind (`pep_offer`, `pd_policy`), doc_version, doc_sha256, accepted_at |
| `templates` | id, code (`uslugi`), doc (`contract`, `act`), version, file_path, file_sha256, fields_schema (jsonb), is_active |
| `documents` | id, number, kind (`contract`, `act`), parent_id (акт → договор), template_id, initiator_id, counterparty_id, customer_id, executor_id, status, current_version, invite_token_hash, invite_expires_at |
| `document_versions` | id, document_id, version, values (jsonb, все подставленные значения), pdf_path, pdf_sha256, created_by, created_at |
| `signatures` | id, version_id, user_id, role, otp_hash, otp_expires_at, attempts, sms_id, signed_at |
| `audit_log` | id, document_id, event, actor_user_id, payload (jsonb), doc_sha256, prev_hash, record_hash, created_at |
| `reminders` | id, document_id, kind, recipient_id, run_at, sent_at, cancelled_at |
| `payments` | id, user_id, document_id, provider, amount, status — плата за договор |

Паспорт и адрес — шифрование AES-GCM на уровне приложения, ключ в переменных окружения.
Номер договора — `CL-YYYY-NNNNNN` из последовательности.

## 9. Безопасность и 152-ФЗ

- Уведомление РКН до запуска; хостинг БД, файлов и бэкапов — в РФ.
- Паспорт и реквизиты не уходят в ИИ и в логи; телефон в логах маскируется.
- Доступ к документу — только две стороны и админ; проверка на каждом действии.
- Ссылка-приглашение: токен 32 байта, в БД только хеш, срок 7 дней, привязывается к первому открывшему.
- Удаление аккаунта: данные и документы хранятся 30 дней, затем уничтожаются. Экземпляры у другой стороны остаются.
- Бэкап БД ежедневно, хранение 30 дней.

## 10. Архитектура и стек

Python 3.12 · aiogram 3 · SQLAlchemy 2 (async) + Alembic · PostgreSQL 16 · Redis (FSM и очередь) · arq (воркер) · LibreOffice headless (DOCX → PDF) · lxml · GigaChat API · SMS-шлюз · S3-совместимое хранилище в РФ · Docker Compose · pytest.

Два процесса: `bot` (диалоги, webhook за nginx; в разработке — polling) и `worker` (PDF, СМС, напоминания, лист подписания).

```
closer/
  bot/handlers/        экраны и диалоги
  bot/keyboards.py
  services/            extract (ИИ), sign (OTP), documents, audit, billing, reminders
  documents/           docx_fill.py, parties.py, signing_sheet.py
  integrations/        gigachat.py (LLMClient), sms.py (SmsGateway), storage.py
  db/models.py, db/migrations/
  worker/tasks.py
templates/uslugi/      contract.docx, act.docx, fields.json
texts/ru.yaml          все тексты бота
docs/                  spec.md, pep_offer.md
tests/
tools/fill_example.py  проверка шаблонов
```
